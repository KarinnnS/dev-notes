## 1. Установка PostgreSQL

**PostgreSQL** — система управления реляционными базами данных (СУБД), которая позволяет создавать, хранить и обрабатывать данные с помощью SQL.

### Шаг 1. Скачивание

1. Перейти на официальный сайт: https://www.postgresql.org/download/
2. Выбрать операционную систему (Windows, macOS или Linux).
3. Скачать подходящий установщик PostgreSQL.
4. Запустить установщик.

### Шаг 2. Установка

Во время установки необходимо:

1. Выбрать папку для установки программы.
2. Выбрать компоненты:

   * **PostgreSQL Server** — сервер базы данных.
   * **pgAdmin 4** — графический инструмент управления базами данных.
   * **Command Line Tools** — инструменты командной строки.
   * **Stack Builder** — дополнительные компоненты (необязательно).
3. Указать папку для хранения данных.
4. Создать пароль для пользователя `postgres` (администратор базы данных).
5. Указать порт подключения (по умолчанию `5432`).
6. Выбрать локаль (обычно можно оставить значение по умолчанию).
7. Завершить установку.

**Важно:**

* Пароль пользователя `postgres` понадобится при подключении к базе данных.
* Порт `5432` используется PostgreSQL по умолчанию, но его можно изменить.
* Устанавливать все дополнительные компоненты необязательно.

## 2. Установка и настройка DBeaver

**DBeaver** — графическая программа для работы с базами данных. Позволяет подключаться к PostgreSQL, создавать таблицы, выполнять SQL-запросы и просматривать данные.

### Шаг 1. Установка DBeaver

1. Перейти на официальный сайт: https://dbeaver.io/download/
2. Скачать **DBeaver Community Edition** для своей операционной системы.
3. Запустить установщик и выполнить установку.
4. Открыть DBeaver.

### Шаг 2. Подключение к PostgreSQL

1. В DBeaver выбрать **Database → New Database Connection**.
2. В списке баз данных выбрать **PostgreSQL**.
3. Заполнить параметры подключения:

| Параметр | Описание             | Пример                         |
| -------- | -------------------- | ------------------------------ |
| Host     | Адрес сервера        | `localhost`                    |
| Port     | Порт PostgreSQL      | `5432`                         |
| Database | Название базы данных | `postgres`                     |
| Username | Имя пользователя     | `postgres`                     |
| Password | Пароль пользователя  | Пароль, заданный при установке |

4. Нажать **Test Connection** для проверки подключения.
5. Если DBeaver предложит скачать драйвер PostgreSQL, подтвердить загрузку.
6. При успешной проверке нажать **Finish**.

### Шаг 3. Проверка подключения

После подключения база данных появится в панели **Database Navigator**.

Для проверки можно открыть SQL Editor и выполнить запрос:

```sql
SELECT version();
```

Команда выводит информацию об установленной версии PostgreSQL.

**Важно:**

* PostgreSQL Server должен быть запущен.
* `localhost` используется при подключении к серверу на том же компьютере.
* При подключении к удалённому серверу необходимо указать его адрес и соответствующие параметры доступа.
* Пароли не следует сохранять в файлах GitHub, даже в приватных репозиториях.

## 3. Создание базы данных

После подключения к PostgreSQL можно создавать собственные базы данных для хранения информации.

### Шаг 1. Создание базы данных через DBeaver

1. Открыть DBeaver и подключиться к PostgreSQL.
2. В панели **Database Navigator** найти подключение к серверу.
3. Найти раздел **Databases**.
4. Нажать правой кнопкой мыши на **Databases**.
5. Выбрать **Create New Database** (название пункта может отличаться в зависимости от версии DBeaver).
6. Указать название новой базы данных.
7. Подтвердить создание.

### Шаг 2. Создание базы данных через SQL

Базу данных также можно создать с помощью SQL-команды.

**Синтаксис:**

```sql
CREATE DATABASE database_name;
```

Где `database_name` — название создаваемой базы данных.

**Пример:**

```sql
CREATE DATABASE lesson15;
```

Эта команда создаёт базу данных с названием `lesson15`.

### Шаг 3. Подключение к новой базе данных

После создания базы необходимо подключиться к ней, чтобы создавать таблицы и выполнять запросы.

В DBeaver можно создать новое подключение или изменить настройки существующего, указав название новой базы в поле **Database**.

**Важно:**

* Название базы данных должно быть уникальным в пределах одного сервера PostgreSQL.
* Для создания базы пользователь должен обладать соответствующими правами.
* Команду `CREATE DATABASE` в PostgreSQL необходимо выполнять вне блока транзакции.
* Создание базы данных не создаёт автоматически пользовательские таблицы.

## 4. Создание пользователей PostgreSQL

В PostgreSQL для управления доступом используются **роли (Roles)**.

Роль может представлять пользователя, группу пользователей или набор прав доступа.

Роль с правом `LOGIN` может подключаться к PostgreSQL как пользователь.

### Шаг 1. Создание пользователя через SQL

**Синтаксис:**

```sql
CREATE USER user_name WITH PASSWORD 'password';
```

* `CREATE USER` — создаёт роль с возможностью входа.
* `user_name` — имя нового пользователя.
* `PASSWORD` — задаёт пароль для подключения.

**Пример:**

```sql
CREATE USER student WITH PASSWORD 'example_password';
```

Создаёт пользователя `student` с указанным паролем.

**Важно:** `example_password` — условное значение. Для реального пользователя необходимо использовать надёжный уникальный пароль. Не публикуйте настоящие пароли в GitHub.

### Шаг 2. Создание роли через CREATE ROLE

**Синтаксис:**

```sql
CREATE ROLE role_name WITH LOGIN PASSWORD 'password';
```

**Пример:**

```sql
CREATE ROLE student WITH LOGIN PASSWORD 'example_password';
```

`CREATE ROLE` с параметром `LOGIN` позволяет создать пользователя, который может подключаться к серверу.

Без `LOGIN` новая роль по умолчанию не сможет самостоятельно входить в PostgreSQL.

### Шаг 3. Создание пользователя через терминал

В Ubuntu можно использовать утилиту `createuser`.

**Синтаксис:**

```bash
sudo -u postgres createuser --createdb user_name
```

**Пример:**

```bash
sudo -u postgres createuser --createdb karyn
```

* `sudo -u postgres` — выполняет команду от имени системного пользователя `postgres`.
* `createuser` — создаёт новую роль PostgreSQL с правом входа.
* `--createdb` — разрешает создавать базы данных.
* `karyn` — пример имени пользователя.

При успешном выполнении команда обычно не выводит сообщение.

Этот способ создаёт пользователя без пароля. Для подключения по паролю его нужно задать отдельно.

### Шаг 4. Установка или изменение пароля

Подключиться к PostgreSQL с административными правами:

```bash
sudo -u postgres psql
```

Внутри `psql` выполнить:

```text
\password user_name
```

**Пример:**

```text
\password karyn
```

PostgreSQL предложит ввести новый пароль и повторить его.

При вводе символы пароля не отображаются.

Команда `\password` удобна тем, что пароль не нужно записывать непосредственно в SQL-запросе.

### Шаг 5. Проверка созданных пользователей

Внутри `psql` выполнить:

```text
\du
```

Команда отображает список ролей PostgreSQL и их основные атрибуты.

**Примечания:**

* Для создания других ролей необходимы соответствующие права, обычно `CREATEROLE` или права суперпользователя.
* Пользователь PostgreSQL и пользователь операционной системы — разные учётные записи.
* Роль с правом `CREATEDB` может создавать базы данных, но не становится суперпользователем.
* Не рекомендуется использовать суперпользователя `postgres` для повседневной работы с учебными проектами.

## 5. Права доступа и владельцы баз данных

В PostgreSQL пользователи могут иметь разные права. Это позволяет управлять тем, кто может создавать базы данных, подключаться к ним и изменять их содержимое.

### Шаг 1. Право на создание баз данных

Чтобы разрешить существующему пользователю создавать базы данных:

```sql
ALTER ROLE student CREATEDB;
```

Чтобы забрать это право:

```sql
ALTER ROLE student NOCREATEDB;
```

**Важно:** `CREATEDB` позволяет создавать новые базы данных, но не предоставляет автоматически все права на чужие базы.

### Шаг 2. Назначение владельца базы данных

У каждой базы данных есть владелец (**OWNER**).

При создании базы можно сразу указать владельца:

```sql
CREATE DATABASE lesson15 OWNER student;
```

Чтобы изменить владельца уже существующей базы:

```sql
ALTER DATABASE lesson15 OWNER TO student;
```

Для изменения владельца необходимы соответствующие права.

Владелец базы может управлять её настройками и рядом прав доступа, но владение базой не означает автоматического владения всеми таблицами внутри неё.

### Шаг 3. Предоставление доступа к базе данных

Чтобы разрешить пользователю подключаться к базе:

```sql
GRANT CONNECT ON DATABASE lesson15 TO student;
```

Чтобы разрешить создавать схемы внутри базы:

```sql
GRANT CREATE ON DATABASE lesson15 TO student;
```

**Важно:** право `CREATE` на уровне базы данных позволяет создавать схемы, но не предоставляет автоматически право создавать таблицы в любой существующей схеме.

Для создания таблиц в схеме `public` можно выдать отдельное право:

```sql
GRANT USAGE, CREATE ON SCHEMA public TO student;
```

Эту команду необходимо выполнять, подключившись к базе `lesson15`.

### Шаг 4. Отзыв прав

Для отмены ранее предоставленного права используется `REVOKE`.

Например:

```sql
REVOKE CONNECT ON DATABASE lesson15 FROM student;
```

Это отзывает право подключения, выданное непосредственно роли `student`. Однако пользователь всё ещё может иметь доступ через другие роли или права `PUBLIC`.

### Шаг 5. Проверка прав

В терминале `psql`:

```text
\du
```

Показывает роли и их атрибуты.

```text
\l
```

Показывает базы данных, владельцев и права доступа.

```text
\dn+
```

Показывает схемы и информацию об их правах в текущей базе.

**Примечания:**

* `GRANT` — предоставляет права.
* `REVOKE` — отзывает права.
* `OWNER` — владелец объекта.
* `CREATEDB` — атрибут роли, позволяющий создавать базы данных.
* Права на базу, схему и таблицы — разные уровни доступа.
* Примеры команд не обязательно выполнять подряд: они показывают разные варианты настройки.

## 6. Работа с PostgreSQL через терминал psql

**psql** — консольный инструмент для подключения к PostgreSQL и выполнения SQL-запросов.

Он позволяет управлять базами данных без графического интерфейса.

### Шаг 1. Подключение к PostgreSQL

В Ubuntu можно подключиться от имени системного пользователя `postgres`:

```bash
sudo -u postgres psql
```

Для подключения под конкретным пользователем через TCP:

```bash
psql -h localhost -p 5432 -U student -d lesson15
```

Параметры команды:

| Параметр | Назначение              |
| -------- | ----------------------- |
| `-h`     | Адрес сервера           |
| `-p`     | Порт подключения        |
| `-U`     | Пользователь PostgreSQL |
| `-d`     | Название базы данных    |

При необходимости PostgreSQL запросит пароль.

### Шаг 2. Основные команды psql

Команды, начинающиеся с обратной косой черты (`\`), являются внутренними командами `psql`, а не SQL-запросами.

| Команда       | Назначение                                |
| ------------- | ----------------------------------------- |
| `\l`          | Показать список баз данных                |
| `\du`         | Показать список ролей                     |
| `\c lesson15` | Подключиться к базе `lesson15`            |
| `\dt`         | Показать таблицы в текущей схеме поиска   |
| `\dn`         | Показать схемы                            |
| `\conninfo`   | Показать информацию о текущем подключении |
| `\?`          | Показать справку по командам psql         |
| `\h`          | Показать справку по SQL-командам          |
| `\q`          | Выйти из psql                             |

### Шаг 3. Выполнение SQL-запросов

Внутри `psql` можно выполнять обычные SQL-запросы.

Например:

```sql
SELECT current_database();
```

Показывает название текущей базы данных.

```sql
SELECT current_user;
```

Показывает текущего пользователя PostgreSQL.

```sql
SELECT version();
```

Показывает версию PostgreSQL.

**Важно:** SQL-запросы обычно заканчиваются точкой с запятой (`;`). Внутренние команды `psql`, такие как `\du` или `\q`, точки с запятой не требуют.

### Шаг 4. Выход из psql

Чтобы завершить работу:

```text
\q
```

После этого произойдёт возврат в обычный терминал операционной системы.

**Примечание:** команда `sudo -u postgres psql` относится к типичной установке PostgreSQL в Linux. В Windows и macOS способ запуска `psql` может отличаться.

## 7. PostgreSQL в Ubuntu/WSL: запуск и проверка

**WSL (Windows Subsystem for Linux)** позволяет запускать Linux внутри Windows.

PostgreSQL можно установить в Ubuntu под WSL, а для работы с базами данных использовать DBeaver в Windows.

> Команды этого раздела предназначены для Ubuntu/WSL. Они не относятся к установке PostgreSQL через обычный Windows-установщик.

### Шаг 1. Установка PostgreSQL в Ubuntu

Открыть терминал Ubuntu и обновить список пакетов:

```bash
sudo apt update
```

Установить PostgreSQL:

```bash
sudo apt install postgresql postgresql-contrib
```

Проверить установленную версию клиента:

```bash
psql --version
```

**Примечание:** версия PostgreSQL зависит от настроенных репозиториев Ubuntu. Для установки конкретной версии могут потребоваться дополнительные действия.

### Шаг 2. Проверка состояния сервера

В Ubuntu с кластерной установкой PostgreSQL можно выполнить:

```bash
pg_lsclusters
```

Пример результата:

```text
Ver Cluster Port Status Owner    Data directory
18  main    5432 online postgres ...
```

* `18` — версия PostgreSQL.
* `main` — название кластера.
* `5432` — порт сервера.
* `online` — сервер запущен.
* `postgres` — системный владелец процесса.

Версия и порт могут отличаться.

### Шаг 3. Запуск и остановка PostgreSQL

Для управления конкретным кластером в Ubuntu:

**Запуск:**

```bash
sudo pg_ctlcluster 18 main start
```

**Остановка:**

```bash
sudo pg_ctlcluster 18 main stop
```

**Перезапуск:**

```bash
sudo pg_ctlcluster 18 main restart
```

Здесь `18` — пример версии PostgreSQL. Перед выполнением команд необходимо проверить свою версию через `pg_lsclusters`.

### Шаг 4. Проверка подключения

Подключиться к PostgreSQL:

```bash
sudo -u postgres psql
```

Проверить текущего пользователя:

```sql
SELECT current_user;
```

Выйти:

```text
\q
```

### Шаг 5. Подключение DBeaver из Windows

Если PostgreSQL работает в WSL2 и доступен через перенаправление localhost, в DBeaver обычно используются следующие параметры:

| Параметр | Пример                         |
| -------- | ------------------------------ |
| Host     | `localhost`                    |
| Port     | `5432`                         |
| Database | `lesson15`                     |
| Username | `student`                      |
| Password | Пароль пользователя PostgreSQL |

Нажать **Test Connection**.

При успешной проверке нажать **Finish**.

Если подключение не работает, необходимо проверить состояние сервера, сетевую доступность, настройки аутентификации и параметры подключения.

### Шаг 6. Распространённые ошибки

**Ошибка: `Peer authentication failed`**

Возникает, когда PostgreSQL использует метод аутентификации `peer`, а имя системного пользователя Linux не соответствует ожидаемой роли PostgreSQL.

Возможные действия:

* Проверить, от какого пользователя выполняется подключение.
* Использовать `sudo -u postgres psql` для административного доступа.
* Для подключения по паролю использовать TCP-подключение с `-h localhost` и убедиться, что у роли задан пароль.

**Ошибка: `Connection refused`**

Возможные причины:

* PostgreSQL не запущен.
* Указан неправильный порт.
* Сервер не принимает подключения по указанному адресу.

Проверить состояние сервера:

```bash
pg_lsclusters
```

**Ошибка: `password authentication failed`**

Возможные причины:

* Неправильный пароль.
* Неправильное имя пользователя.
* Несоответствие настроек аутентификации выбранному способу подключения.

Проверить параметры подключения и при необходимости изменить пароль пользователя.

**Важно:** не следует изменять настройки `pg_hba.conf` или открывать сервер для внешних подключений без понимания последствий для безопасности.
